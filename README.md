# Vibe Stack

Автономный пайплайн Telegram-канала про вайбкодинг и AI-разработку. ИИ (OpenAI `gpt-5.6-terra`) оценивает находки, сверяет утверждения с первоисточником и пишет посты, а код держит лимиты, дедупликацию, проверки ссылок, расписание и баллы.

- Спецификация: [`docs/vibe-stack-package-v2.md`](docs/vibe-stack-package-v2.md)
- Где мы сейчас и что дальше: [`docs/status.md`](docs/status.md)
- Решения и отличия от ТЗ: [`docs/decisions.md`](docs/decisions.md)

## Как это устроено

```
источники → дедуп → prefilter (код) → загрузка → A: оценка → гейт (код) → B: проверка (чистый контекст, свежая загрузка)
          → C: текст → линтер (код) → Notion «Одобрено» / «На одобрении» → публикация по слотам → Telegram
```

| Контур | Команда | Расписание (Actions) |
|---|---|---|
| Сбор | `vibe-stack collect` | дважды в день: 07:00 и 14:00 МСК, запасные запуски 08:30 и 15:30 (`collect.yml`) |
| Срочный | `vibe-stack urgent` | каждые 30 минут (`tick.yml`) |
| План дня | после сбора (`collect`) и на каждом тике | каждому одобренному посту — время на сегодня (Notion «Время публикации»), админу «План на сегодня» |
| Публикация | `vibe-stack publish` | каждые 30 минут выпускает посты, чьё время наступило, до 24 в день (`tick.yml`) |
| Закреп и «Слово дня» | `vibe-stack pin`, `glossary` | закреп-навигатор — с каждым сбором (правится, только если топ изменился); «Слово дня» — с утренним (`collect.yml`) |
| Песочница | `sandbox-export` → `sandbox_runner.py` → `sandbox-apply` | сразу после сбора, запасные запуски днём (`sandbox.yml`) |
| Что посмотреть и послушать | `vibe-stack watchlist` | воскресенье, 12:00 МСК, запасной запуск 13:30 (`weekly.yml`) |
| Итоги недели | `vibe-stack weekly` | воскресенье, 19:00 МСК, запасной запуск 20:30 (`weekly.yml`) |
| Сводка дня админу | `vibe-stack digest` | 23:45 МСК, запасной запуск 23:55 (`digest.yml`) |

Состояние (просмотренное, лимиты, расходы на LLM) хранится в SQLite в ветке `state`. Посты, статусы, рубрики, источники и флажок «Пауза» лежат в Notion.

## Локальный запуск

```bash
uv sync                      # Python 3.12 и зависимости
cp .env.example .env         # заполнить нужные ключи
uv run pytest                # тесты
uv run ruff check .          # линтер
uv run vibe-stack eval       # фикстуры раздела 12: решения совпадают с ожидаемыми
uv run vibe-stack eval --llm real   # те же фикстуры, но с настоящей моделью (нужен OPENAI_API_KEY)
```

Режим по умолчанию — **`--dry-run`**: ничего не публикуется, в Notion ничего не пишется, всё складывается в `out/<run_id>/` (посты, решения по каждому кандидату, лог, `summary.json`).

```bash
uv run vibe-stack collect                # dry-run сбора; без Notion в .env — локальная доска out/local_board.json
uv run vibe-stack publish --now 2026-10-07T07:07:00Z   # dry-run публикации в момент слота 10:00 МСК
uv run vibe-stack status                 # счётчики за сегодня и расходы
uv run vibe-stack collect --publish      # по-настоящему (нужны Notion и Telegram)
```

## Настройка (один раз)

1. **Telegram.** Создайте канал и бота в @BotFather. Сделайте бота админом с правами публикации, редактирования и закрепления. Напишите боту в личку, чтобы он мог присылать вам оповещения.
2. **OpenAI.** Ключ API с доступом к `gpt-5.6-terra`.
3. **Notion.** Создайте внутреннюю интеграцию и пустую страницу «Vibe Stack», затем расшарьте страницу на интеграцию (••• → Connections). Положите `NOTION_TOKEN` и `NOTION_ROOT_PAGE_ID` в `.env` и выполните `uv run vibe-stack notion-setup`: команда создаст все базы, заполнит рубрики и источники и **включит Паузу**.
4. **GitHub.** В Settings → Secrets → Actions добавьте `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `ADMIN_CHAT_ID`, `NOTION_TOKEN`, `NOTION_ROOT_PAGE_ID` и, для видео YouTube, `YOUTUBE_API_KEY` (бесплатный ключ YouTube Data API v3 из Google Cloud Console; без него источник видео пропускается). Расписание включается переменной `VIBE_STACK_ENABLED=true` (Settings → Variables). Без неё workflows запускаются только вручную.
5. Снимите «Паузу» в Notion, когда будете готовы.

## Безопасность

- Код из найденных репозиториев запускается только в песочнице (`sandbox.yml`). Это одноразовая машина GitHub Actions, у job нет ни секретов, ни прав (`permissions: {}`). Контейнеры с кодом пакета работают под gVisor (отдельное ядро-песочница). Установка идёт без выполнения кода пакета: только wheel или npm 11 с `--ignore-scripts` и без git-, URL- и файловых зависимостей. Наружу установка ходит только через прокси и только к PyPI и npm; машина, частные сети и метаданные облака из контейнеров закрыты, и перед каждым запуском это проверяется изнутри контейнеров. Сам пакет запускается только с `--help` в контейнере без сети, не от root, без capabilities, с корнем только на чтение и лимитами памяти, CPU, процессов, вывода и места. Пакет берётся, только если его provenance указывает на репозиторий поста, а без provenance — если сам репозиторий объявляет это имя пакета. Команды строит код по имени пакета, проверенному в PyPI/npm, а текст README не исполняется. Пометку «🧪 Запущено в песочнице» ставит код, и только после успешного запуска. Кэш Actions не используется нигде, где есть секреты или права на запись.
- Всё загруженное считается недоверенными данными: теги `<source_document>` и другие нельзя закрыть изнутри данных, явные фразы-инъекции код ловит сам.
- Секреты читаются только из окружения и вычищаются из логов. `.env` в git не попадает.
- Расходы ограничены лимитом вызовов на запуск (`llm.max_calls_per_run`) и жёстким дневным лимитом токенов на модель (`llm.daily_token_limits`, сейчас 2 млн для gpt-5.6-terra, сутки по UTC). Вызов, который может выйти за лимит, не делается, а вам приходит оповещение. Дополнительно можно включить лимит в долларах (`llm.daily_budget_usd`, сейчас выключен).
- «Пауза» в Notion — аварийный выключатель. Если Notion недоступен, публикации нет.
